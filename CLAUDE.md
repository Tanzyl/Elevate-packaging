# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

**Brand:** the site is **Elevate**, a USA-based flexible packaging manufacturer (domain `elevatepackaging.com`, npm scopes `@elevatepackaging/web` / `@elevatepackaging/api`). The repo started as a template for a different company and was rebranded on 2026-10-26: contact details are placeholders (phone `+1 (555) 010-0100`, `info@elevatepackaging.com` / `careers@elevatepackaging.com`, `123 Industrial Way, Suite 100, Anytown, ST 00000, USA`) and company-history copy is marked `TODO: client copy` in `WEBSITE_CONTENT_INVENTORY.md` until the client supplies real content.

**Security:** the upstream repo shipped with hidden malware, removed 2026-10-26: obfuscated JS appended after long whitespace runs in `api.js` (run by `node api.js &&` in every `dev`/`build`/`start` script), in `apps/web/postcss.config.mjs`, and in a fake font file under `app/admin/categories/[id]/public/fonts/`, auto-run on folder open by a hidden `.vscode/tasks.json`. Treat any reappearance of these — or any script-run step that isn't a known tool — as hostile, and don't run code from upstream merges without checking for it.

## Repository shape

The root holds planning docs and the actual application code under `website/`. Always `cd website/` before running dev commands — the pnpm workspace and Docker Compose file live there, not at the repo root. (If the session started in a parent folder rather than the repo root, descend one more level first.)

```

  WEBSITE_CONTENT_INVENTORY.md      (authoritative copy, contact, certs, sitemap)
  PRODUCT.md                        (product context record: platform, user segments, positioning —

  DESIGN.md                         (design-system record: named palette, typography, radii tokens —
                                     mirrors tailwind.config.ts/globals.css; keep in sync if tokens change)
  PRODUCT_IMAGE_PROMPTS.md          (per-product image-asset prompts / manifest)
/website/                      ← pnpm workspace root
  apps/web/  — Next.js 14 App Router, Tailwind, Framer Motion + Lenis, tsparticles; admin forms use react-hook-form + zod, TanStack Query, sonner toasts
  apps/api/  — NestJS 10, Prisma 5, JWT + Passport
  docker-compose.yml  — Postgres 16 on host :5434
```

**Line endings are mixed** — there's no `.gitattributes` and `core.autocrlf` is off, so editors that normalize CRLF/LF produce whole-file `git diff` rewrites with zero real change (recently: `tsconfig.json`, `whatsapp-button.tsx`, `.gitignore`, `WEBSITE_CONTENT_INVENTORY.md`). When reviewing a suspiciously large diff, check for this before assuming the file was rewritten — `git diff --stat --ignore-cr-at-eol <file>` shows the real change size. Related noise: `apps/web/tsconfig.tsbuildinfo` is a **tracked** build artifact that TypeScript rewrites on every build — its diffs carry no information; ignore it (and don't let it pad commits).

**Load-bearing files have historically landed untracked** — new components have shipped importable-from-committed-code while existing only in the working tree and **it has happened again**: as of 2026-10-28, `components/theme-toggle.tsx`, `components/sections/process.tsx`, `components/company/`, `components/products/`, `components/industries/{cta-band,photo-tile}.tsx`, `app/icon.svg`, and `public/images/logo{,-dark}.svg` are untracked but imported by committed pages (home, navbar, about, blog, contact, products, industries, businesses). Commit them together with the code that imports them. The habit to keep: run `git status` before `git stash` (use `-u`) or `git clean -fd`, and before declaring a Vercel build of `main` reproducible.

## Commands

Run from `website/`:

```bash
cp .env.example .env          # once
pnpm install
pnpm db:up                    # Postgres in Docker (host :5434)
pnpm --filter @elevatepackaging/api prisma:migrate

pnpm dev                      # web :3002 + api :4000 in parallel
pnpm web dev                  # web only
pnpm api dev                  # api only
pnpm build                    # build both apps
pnpm lint                     # lint both apps

pnpm --filter @elevatepackaging/api prisma:studio       # Prisma Studio
pnpm --filter @elevatepackaging/api prisma:generate     # regen Prisma client
pnpm --filter @elevatepackaging/api prisma:seed         # seed catalog + admin user (needs SEED_ADMIN_PASSWORD)
```

The seed (`apps/api/prisma/seed.ts`) **imports from `apps/web/lib/products.ts` and `images.ts`** to round-trip the existing code-driven catalogue into Postgres. That cross-app import is intentional but fragile — if you rename or restructure those `web/lib` files, the seed compile breaks. Run the seed after the first migration to populate the admin login and the public catalog. **There is no committed default admin password any more** (removed in `aab6d88`): the seed refuses to run unless `SEED_ADMIN_PASSWORD` (≥12 chars) is set, the email defaults to `admin@elevatepackaging.com` (override via `SEED_ADMIN_EMAIL`), and re-seeding never resets an existing admin's password.

`apps/api/prisma/sync-catalog.ts` is a companion **one-off** script (not wired as a `package.json` script) that re-syncs **only** categories + products from `products.ts` — pruning any category/product whose slug is no longer in the code catalogue, then upserting the rest — while leaving markets, innovations, news, testimonials, gallery, videos, and users untouched. Product galleries prefer `products.ts` → existing DB gallery → the curated `img.products[slug]` seed image, in that order. Use it (not the full seed) when the catalogue changed but you don't want to touch other content. Run: `pnpm --filter @elevatepackaging/api exec ts-node --compiler-options '{"module":"CommonJS"}' prisma/sync-catalog.ts`.

**No test framework is wired up yet.** Neither app has a `test` script and jest/vitest are not in `package.json`. Don't run `pnpm test` — it will fail. If tests are needed, pick a framework first (Phase 2/3 work). Verify this is still true before trusting it: `grep -l '"test"' apps/*/package.json` from `website/` should print nothing. The one exception is a standalone assert script guarding the JSON-LD XSS escaping: `node lib/json-ld.test.mjs` from `apps/web/` (it mirrors `safeJsonForScript()` in `components/json-ld.tsx` rather than importing it — change both together).

**Non-standard ports** (host 5432/3000 were taken on the dev machine): Postgres is on **5434** and Next.js on **3002**, API on **4000**. Don't "fix" these back to defaults without checking — they're hard-coded in multiple places:
- `website/docker-compose.yml` line 11 (`"5434:5432"`) — Postgres host port
- `website/apps/web/package.json` `dev` and `start` scripts (`next dev -p 3002`) — Next.js port
- `website/apps/api/src/main.ts` (`Number(process.env.PORT ?? 4000)`, ~line 25) — API port (overridable via `PORT` env)
- `website/.env` / `.env.example` `DATABASE_URL` — must match the Postgres host port

Health check: `curl http://localhost:4000/health` → `{"status":"ok","ts":"..."}`.

## Architecture

**Monorepo** via `pnpm-workspace.yaml` (packages: `apps/*`). Node ≥ 20.10, pnpm 9.15.1 pinned in root `package.json`.

**Env resolution is split, not shared**: `apps/api/src/app.module.ts` loads `ConfigModule` with `envFilePath: ["../../.env", ".env"]`, so the API reads `website/.env`. **Next.js does not** — it only reads `apps/web/.env*` (there is a gitignored `apps/web/.env.local`, created by the Vercel CLI), so `NEXT_PUBLIC_*` vars such as `NEXT_PUBLIC_FORM_ENDPOINT` must go there (or in Vercel project env for prod). Putting them in `website/.env` does nothing for the web app even though `.env.example` lists them there.

**Frontend (`apps/web`)**:
- App Router under `app/`. Public marketing pages: `about`, `products`, `industries`, `our-businesses`, `innovations`, `media`, `blog`, `contact`, `rfq` (`careers` was removed 2026-10-26). **`markets`, `services`, and `sustainability` public pages were deleted** (commit `a45945b` "Remove Markets, Sustainability & Services pages + their links") — don't re-add them or link to them without asking. Dynamic segments: `app/products/[category]/page.tsx`, `app/products/[category]/[slug]/page.tsx`, and `app/industries/[slug]/page.tsx` (per-industry detail page — `generateStaticParams` over all 25 industry slugs, its own `generateMetadata`/breadcrumb JSON-LD, and a related-industries grid). Plus `app/our-businesses/[slug]/page.tsx` (per-business detail page over the 6 units in `lib/businesses.ts`, which carries the long-form `overview`/`capabilities`/`highlights`/`relatedProducts` copy for them). And `app/blog/[slug]/page.tsx` (per-post article page with its own small parser for the markdown-ish bodies: `##` headings, lists, `|` tables; `app/blog/page.tsx` is the index; params come from `getNews()` so it follows the API-or-fallback rule). There is deliberately **no** second article route under `/media` — the Media page is the teaser, `/blog` is the archive. Those five are the only routes with `generateStaticParams`. The admin panel is at `app/admin/*` (regular routes, **not** the older `(admin)` route group — that group has been removed). Admin sub-pages: `categories`, `products`, `markets`, `inquiries`, `innovations`, `news`, `gallery`, `videos`, `testimonials`, `certifications`, plus `login`. (`news`/`gallery`/`videos` are the Media-page CMS — each has `new` and `[id]` edit routes.)
- **Orphaned-by-design: the Markets stack.** The public Markets pages are gone, but `app/admin/markets/*`, `components/admin/market-form.tsx`, the API `markets/` module, the Prisma `Market` model, and `getMarkets`/`getMarketBySlug` + `FALLBACK_MARKETS` in `lib/content-source.ts` all still exist with **no public consumer**. Treat them as dormant, not broken — if you're asked to clean up dead code, this is the cluster to raise, and removing any one layer without the others will break the admin build.
- **Admin auth is enforced in `middleware.ts`**, and since the security-hardening commit `aab6d88` it actually *verifies* the `pp_session` JWT (HS256 signature + expiry via WebCrypto, rejecting `alg: none`) instead of just checking cookie presence; invalid/missing → redirect to `/admin/login?from=…` (the `from` redirect is restricted to same-origin paths). **In production the whole `/admin` tree — including the login page — is disabled unless `ADMIN_ENABLED=true`.** The cookie is set by the API on `/auth/login` and matches `SESSION_COOKIE` in `apps/api/src/auth/jwt.strategy.ts`; middleware and API must share the same `JWT_SECRET`.
- **`components/client-chrome.tsx`** wraps all routes in `app/layout.tsx`. It short-circuits the public chrome (navbar, footer, page transitions, Lenis smooth scroll, WhatsApp button, chat widget, route-progress bar, page loader) for any path starting with `/admin` so the admin panel renders inside its own shell (`components/admin/admin-shell.tsx`).
- **`components/chat-widget.tsx` is a scripted keyword bot, not the Phase-3 AI chat.** It floats above the WhatsApp button, keyword-matches questions in its local `answer()` function, and builds replies from the same static data the pages use (`products.ts`, `site-config.ts`) — no backend, so it works on static hosting. The Phase-3 AI chat is meant to swap `answer()` for a real API call without touching the widget UI. `components/route-progress.tsx` is the thin accent bar under the top edge that starts on any same-origin link click and completes when the route renders.
- **Public content is API-first with a static fallback**: `lib/content-source.ts` (server-only) hits the NestJS endpoints (`/categories`, `/products/:slug`, `/innovations`, `/news`, `/gallery`, `/videos`) with `next: { revalidate: 60 }` and falls back to in-file `FALLBACK_*` consts / `lib/products.ts` if the API is unreachable. **In practice production runs entirely on the fallbacks** — the API is not deployed (see Deployment below), so the `FALLBACK_INNOVATIONS` / `FALLBACK_GALLERY` / `FALLBACK_VIDEOS` arrays (and `newsPosts` in `lib/news-data.ts`) *are* the live Innovations and Media page content. Edit those (or `products.ts`) to change what the deployed site shows; editing via the admin panel only affects a local DB. New public pages should still import from `content-source.ts`, not `products.ts` directly. Static `lib/site-config.ts`, `lib/content.ts`, `lib/products.ts`, `lib/home-content.ts`, `lib/images.ts`, plus `lib/businesses.ts` (the "Our Businesses" group) and `lib/industries.ts` (**25** industries in 4 `industryGroups` + `industriesByGroup`, plus the `getIndustryBySlug`/`relatedIndustries`/`groupSlug`/`industriesForApplications` helpers used by the `industries` list and `[slug]` detail pages and rendered via `components/industries/industry-card.tsx`) still hold the canonical copy/nav/images and **must stay in sync with `../WEBSITE_CONTENT_INVENTORY.md`**. `lib/video.ts` is a pure helper (`parseVideo`) that turns a YouTube/Vimeo URL into an embed URL + thumbnail — used by the videos CMS and any embedded player.
- **The Media page's Gallery section is composed, not just fetched**: `app/media/page.tsx` shows the curated gallery (from `content-source.ts`) by default, and pools **every** industry photo from the `images` arrays in `lib/industries.ts` (deduped by URL) into a "View all N photos" toggle rendered by the client component `components/media/gallery-grid.tsx`. Adding photos to an industry automatically grows the expanded Media gallery. The News section is likewise a client component, `components/media/news-section.tsx` (commit `c6783d0`): a lead story (cover photo + first two body paragraphs) plus a ruled index with thumbnails where clicking a row promotes it to the lead with an animated swap — the lead defaults to the first `featured` post, and every story links to its `/blog/<slug>` article page. **The news posts themselves live in `lib/news-data.ts`** (`newsPosts`, optional `seoTitle`, body = markdown-ish text: blank-line paragraphs plus `##` headings and `|` tables that only `/blog/[slug]` renders): `content-source.ts` uses it as `FALLBACK_NEWS` *and* `apps/api/prisma/seed.ts` imports it for the `NewsPost` table, so there is one copy to edit — re-run the seed after changing it if you want the local DB to match. Date formatting and body-paragraph splitting are the shared helpers in `lib/news.ts` (plain module, no `"use client"`, so server pages can call them; `newsParagraphs` skips heading/table/list lines so the Media teaser stays prose); dates render via `toLocaleDateString` pinned to `timeZone: "UTC"` (ISO date-only strings parse as UTC midnight, so local-zone formatting showed the previous day) — keep that pin on any new date formatting.
- **`components/language-switcher.tsx` is machine translation, not real i18n** (commit `df1d2de`). A floating flag pill (bottom-left, rendered from `client-chrome.tsx` so it's public-chrome-only) sets the Google Translate `googtrans` cookie and reloads; the widget script loads only when a non-English cookie is present and rewrites the DOM in place — EN/ES/FR/AR, no locale routes, no translated data files. Supporting wiring you'll trip over if you don't know it's there: the CSP in `next.config.mjs` allowlists three Google Translate hosts (script-src + style-src); `globals.css` has `html.translated-*` rules that shrink header labels so the nav stays one row (Arabic gets an RTL small-text bump) and hides the widget's banner/tooltip chrome; the WhatsApp button and the switcher itself are `notranslate`; `chat-widget.tsx` normalizes visitor input to English for its keyword matcher and translates scripted replies back; `page-loader.tsx` self-translates its tagline from the cookie. The upgrade path (marked in the component) is next-intl locale routes with human-translated `lib/*.ts` data — that's the out-of-scope "multi-language" item, so don't start it without a change request.
- **No em dashes in user-visible copy.** Commit `c6783d0` swept them out of news bodies, chat-widget replies, page titles, alt text, email subjects, and JSON-LD names — rephrase with commas/periods/colons instead when writing new copy. (Code comments and docs like this file are fine.)
- **Contact + RFQ forms bypass the API entirely.** `lib/submit-form.ts` POSTs a `FormData` payload straight to a third-party handler at `NEXT_PUBLIC_FORM_ENDPOINT` (currently FormSubmit, `https://formsubmit.co/ajax/<email>`; Formspree/Web3Forms/Basin work the same way), returning `"sent" | "error" | "unconfigured"` — `"unconfigured"` when the env var is empty, which is the default in `.env.example`. FormSubmit answers HTTP 200 with `success:"false"` when the form is not yet activated, so `submit-form.ts` reads the JSON body and maps that to `"error"` (commit `97bb52e`) — keep that check if you swap providers. Used by `components/contact-form.tsx` and `components/rfq-form.tsx` (each passes an `_subject` extra). Consequence: **nothing writes to the API's `Inquiry` table any more**, so `/admin/inquiries` only ever shows rows created before this change. Don't "fix" the forms to POST to `/inquiries` without confirming — going through a static form handler is deliberate, so the site works without a backend.
- **Navigation is a composed mega-menu**, not a flat navbar. `lib/mega-nav.ts` builds `MEGA_ITEMS` at module load by composing `catalog` (from `products.ts`), `industriesByGroup` (from `industries.ts`), and `businesses` (from `businesses.ts`, linking to `/our-businesses/<slug>` detail pages), assigning a distinct Lucide icon per leaf. It feeds `components/ui/mega-menu.tsx` via `components/navbar.tsx`. To change what appears in the Products/Industries/Businesses dropdowns, edit the source `lib/*.ts` data, not the menu component. Top-level entries with a panel (Our Businesses, Products, Industries) also carry a `link` — `mega-menu.tsx` renders those as `Link`s that **navigate on click and open the dropdown on hover** (a `link`-less panel item would render as a hover-only button instead), and highlights the current section via a `usePathname()` prefix match (accent underline + `aria-current`). Industry leaf links go to the `/industries/<slug>` detail pages, not `/industries#<slug>` hash anchors — that holds in both `mega-nav.ts` and the `nav.primary` tree in `site-config.ts` (consumed by `site-footer.tsx` and a mobile quick-links strip in `navbar.tsx`), so keep them consistent if you change one. **There is no separate `mobile-menu.tsx`** — the mobile drawer is the recursive `MobileEntry` tree inside `navbar.tsx`, walking the same `MEGA_ITEMS` (so Industries arrive already grouped by category), and while open it stops Lenis and locks `document.body` overflow so only the drawer scrolls (commit `40ea74b`).
- **Admin fetch uses `lib/admin-api.ts`** — a thin wrapper that always sends `credentials: "include"` (so the `pp_session` cookie rides along) and exports typed shapes (`AdminCategory`, `AdminProduct`, `AdminMarket`, `AdminInquiry`, `AdminInnovation`, `AdminTestimonial`, `AdminCertification`). Forms in `components/admin/` (e.g. `product-form.tsx`, `category-form.tsx`, `market-form.tsx`, `innovation-form.tsx`, `image-uploader.tsx`) are built around these types.
- Bulk media lives under `apps/web/public/images/` (subfolders: `products`, `industries`, `innovations`, `businesses`, `capabilities`, `certifications`, `clients`, `partners`) and `apps/web/public/videos/` (currently only a `README.md` — the hero video is not committed). Admin-uploaded images are served by the API at `/uploads/products/<uuid>.<ext>` (see backend section).
- **All committed imagery is WebP.** Commit `d29489c` converted the tree from ~300MB of source JPG/PNG down to ~17MB of `.webp` and replaced raw YouTube embeds with a facade component (`components/ui/lite-video.tsx` — click-to-load thumbnail, no iframe until interaction). Keep new photos in `.webp` and route new embeds through `lite-video.tsx`; dropping a 4MB JPG into `public/images/` undoes the win. Naming convention is `<slug>-NN.webp` (e.g. `rice-packaging-01.webp`), which is what the `images: [...]` arrays in `lib/industries.ts` and the `img.*` helpers in `lib/images.ts` expect. `lib/images.ts` also still contains legacy remote-placeholder generators (`pexels()`, `lf()` loremflickr) for anything without real photography — the `next.config.mjs` `remotePatterns` allowlist exists for those — since `aab6d88` the patterns are **pinned to specific paths** (no open image proxy) and the `localhost:4000` loopback entry is dev-only.
- **Security headers + service worker live in `next.config.mjs` and `public/sw.js`** (both from `aab6d88`). `next.config.mjs` sets a CSP (`script-src 'self' 'unsafe-inline'` — a nonce would force every page dynamic; dev adds `'unsafe-eval'` for HMR; `frame-src` allowlists YouTube/Vimeo for `lite-video.tsx`), X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy, and HSTS. Adding a new external script/frame/font source means updating that CSP or it will be blocked in prod. `public/sw.js` (registered from `client-chrome.tsx`) caches images stale-while-revalidate; image output includes AVIF with a 1-year optimized-image cache — remember the SW when debugging "stale image" reports.
- **Light + dark themes, both driven by CSS-var tokens.** `components/theme-provider.tsx` (next-themes, `attribute="class"`, `defaultTheme="system"`) toggles `.dark` on `<html>`; `components/theme-toggle.tsx` is the sun/moon button in the navbar. `app/globals.css` defines light tokens on `:root, .force-light` (warm paper `--bg`, ink `--fg`, evergreen `--accent` `#1f5f47`) and dark tokens on `.dark` (deep forest `--bg` `#0e1411`, lifted `--accent` `#3d8f6b`) — components use the semantic tokens and need no `dark:` variants. `.force-light` pins the admin panel (`app/admin/layout.tsx`) to light. `.band-dark` redefines the tokens for the dark evergreen home-page bands. `BrandLogo` swaps `logo.svg`/`logo-dark.svg` via `dark:`. Design tokens in `tailwind.config.ts`: `primary` (evergreen scale, 600 = `#1f5f47`), `gold` (copper scale, 500 = `#c56b36`), `print` (earthy decorative dots), and `navy` (warm charcoal). Style with the semantic tokens mapped to the CSS vars (`bg-bg`, `bg-section`, `bg-card`, `text-fg`, `text-muted`, `border-line`, `bg-accent`), not raw `primary`/`navy` scales. Custom Tailwind breakpoint `nav: 1280px` (raised from 1100 when nav labels became nowrap) — the full horizontal header nav only renders ≥1280px; below it the mobile menu shows.
- Fonts: **Plus Jakarta Sans** (display) + **DM Sans** (sans), loaded via `next/font/google` in `app/layout.tsx` as CSS vars `--font-display` / `--font-sans` (Tailwind `font-display`/`font-sans` fall back to Georgia-serif / system-ui if the web fonts fail). Don't swap without confirming with the user.
- **SEO**: `lib/seo.ts` centralises Next.js `Metadata` construction (titles, OG/Twitter, canonical, `SITE_URL`) — reuse it in page `generateMetadata`. `app/sitemap.ts` and `app/robots.ts` generate the sitemap/robots routes. `sitemap.ts` enumerates a hard-coded `STATIC_PATHS` array plus category/product slugs from `catalog` **and all 25 `/industries/[slug]` detail routes from `industries`** (industries coverage added in the SEO-audit commit `28bb769`). Note it imports `catalog` from `products.ts` and `industries` from `industries.ts` directly (not `content-source.ts`), so the sitemap always reflects the static data — a new route family needs a matching loop added there.
- **Motion primitives** live in `components/motion/` — reusable wrappers (`reveal`, `magnetic`, `cursor-glow`, `page-transition`, `smooth-scroll`, `split-reveal`) plus `use-count-up.ts` and `tokens.ts` (shared `ease` curves and `dur` durations). New animated sections should import these tokens and primitives instead of re-deriving easings or re-wiring Framer Motion variants per file. Smooth scrolling is provided by Lenis via `motion/smooth-scroll.tsx`; particle effects come from `components/ui/sparkles.tsx` (tsparticles).
- **Logo strips use `components/ui/marquee.tsx`** — a pure-CSS marquee (two copies of the content, transform-only `animate-marquee` keyframes in `globals.css`, so it stays smooth on the GPU compositor even while Lenis/reveals run). The home-page client-logo strip ("Top Clients", `top-clients.tsx`, which used it with a **seeded** Fisher–Yates shuffle because `Math.random()` would break SSR hydration), the partners strip, and testimonials were **removed in the Elevate rebrand** (they named the previous company's clients/partners) — don't restore them until the client supplies real logos/quotes. It replaced the JS/rAF `components/ui/infinite-slider.tsx`, which is now only imported by the already-orphaned `big-marquee.tsx`; `ui/shifting-nav.tsx` is likewise imported by nothing — both belong to the dead-code cluster.

**Backend (`apps/api`)**:
- NestJS modules under `src/`: `health/`, `auth/`, `prisma/` (shared `PrismaService`), plus the Phase-2 CRUD modules `categories/`, `products/`, `markets/`, `inquiries/`, `innovations/`, `news/`, `gallery/`, `videos/`, `site-content/`, and `uploads/`. All are wired in `app.module.ts`. (`news`/`gallery`/`videos` back the public Media page and its admin CMS.) **Two module layouts coexist**: `auth`, `categories`, `products`, `inquiries`, `uploads` use the conventional controller/service/dto split, while `gallery`, `innovations`, `markets`, `news`, `videos`, and `site-content` are each a **single `<name>.module.ts` file** holding DTOs + service + controller + module together. `site-content/` is the odd one out by name: it bundles the `Testimonial` and `Certification` CRUD (`/testimonials`, `/certifications`) because neither warranted its own folder — look there, not for a `testimonials/` directory.
- **Auth uses HttpOnly cookies, not `Authorization: Bearer`.** `auth.controller.ts` issues a JWT in the `pp_session` cookie (sameSite `lax`, Secure by default, default 7-day TTL via `SESSION_DAYS`). **The API refuses to boot without a real `JWT_SECRET` of ≥32 chars** — the old `change-me-in-prod` fallback is gone (`aab6d88`). Routes are protected with `@UseGuards(JwtAuthGuard)`; admin-only endpoints add `RolesGuard` + `@Roles(...)` (see `auth/roles.guard.ts`, `auth/roles.decorator.ts`). **Role convention across every CRUD module**: create/update and the drafts-included `GET /<resource>/admin/list` are `Role.ADMIN, Role.EDITOR`; **every `DELETE` is `Role.ADMIN` only** — keep that split when adding endpoints. The user's role is **re-resolved from the DB per request** (not trusted from the JWT claim), so demoting/deleting a user takes effect immediately. Login runs a constant-time bcrypt compare to avoid an account-enumeration timing oracle. The `/auth/me` endpoint returns the current user; `/auth/logout` clears the cookie. CORS is restricted to `WEB_ORIGIN` (default `http://localhost:3002`) with `credentials: true`.
- **File uploads**: `POST /uploads/image` (admin-only) accepts multipart `file`, stores via multer at `apps/api/uploads/products/<uuid>.<ext>` (10MB limit, jpg/jpeg/png/webp/gif/avif only — **verified by magic bytes, not just extension/MIME**), and returns `{ url, path, size, mime }`. Static files are served at `/uploads/*` via `app.useStaticAssets(UPLOAD_ROOT, …)` in `main.ts` with `nosniff` + a sandbox CSP. `UPLOAD_ROOT` is created on boot. The `apps/api/uploads/` directory is intentionally on disk (not in S3 yet — S3-compatible media is locked-in for later).
- Public `bySlug` routes (products, innovations, markets) **filter out unpublished drafts** — don't remove that filter when touching those services.
- Prisma schema at `apps/api/prisma/schema.prisma`. Current models: `User` (ADMIN/EDITOR role enum), `Innovation` (has optional `videoUrl`), `ProductCategory` ↔ `Product` (1-to-many, cascade delete), `Market`, `Inquiry`, `Testimonial`, `Certification`, plus the Media-page CMS models `NewsPost`, `GalleryImage`, `Video`. Slugs are unique on the slug-bearing content models. `Product.specs` and `Product.gallery` are `Json` columns; `Product.description`/`applications`/`features`/`finishes` and `Market.applications` are `String[]`.
- CORS is on globally (`main.ts`); `ValidationPipe` with `whitelist: true, transform: true` is applied globally — DTOs use `class-validator` decorators. `cookieParser()` is applied as global middleware.
- Migrations live in `apps/api/prisma/migrations/` (4 so far: `init`, `admin_panel`, `media_cms`, `innovation_video`). Schema changes need a new `prisma:migrate` — don't hand-edit existing migration SQL.

## Deployment

**`apps/web` deploys to Vercel; `apps/api` is not deployed anywhere.** That single fact explains most of the frontend architecture above:

- `apps/web/.vercel/project.json` pins the linked Vercel project, and `apps/web/vercel.json` pins `framework: "nextjs"` and sets `installCommand: "pnpm install --no-frozen-lockfile"` — i.e. Vercel builds from `apps/web` as its own project (note it carries a second `pnpm-lock.yaml` alongside the workspace root's) and the frozen-lockfile check is deliberately off. Leave that flag alone unless you've confirmed a clean frozen install from `apps/web`.
- **`tsconfig.json` is pinned to TypeScript 5.6.3 (`apps/web/package.json`)** — an upstream edit added `"ignoreDeprecations": "6.0"` (valid only on TS ≥5.9) to silence an editor warning about `baseUrl`, and `next build` failed with `TS5103: Invalid value for --ignoreDeprecations` on Vercel until it was removed. Don't re-add it; if the `baseUrl` deprecation warning bothers you, delete `baseUrl` and keep `paths` (they resolve relative to the tsconfig since TS 4.1) instead.
- **`lib/site-config.ts` gets edited directly on `main` outside a dev environment** (commits `e0f6137`/`4ab43b3`, "Update site-config.ts"), and one such edit shipped an unquoted phone number that broke the build until `2f965c0`. After pulling, run `pnpm web build` (or at least `pnpm --filter @elevatepackaging/web exec tsc --noEmit`) before assuming `main` compiles; when a `site-config.ts` diff looks huge, it is usually the CRLF noise described above plus a one-line real change.
- Because no API is reachable in production, every `tryFetch` in `content-source.ts` fails fast and the site renders from the in-repo fallbacks, and the forms go to `NEXT_PUBLIC_FORM_ENDPOINT` instead of `/inquiries`. **A content change only ships if it lands in `lib/*.ts`.**
- The admin panel and the whole NestJS + Postgres stack are therefore local-dev / future-hosting infrastructure, not the live editing path. Don't assume an admin-panel edit is visible on the deployed site.
- `next.config.mjs` uses the default (server) output — there's no `output: "export"` — but the code is written to tolerate static hosting (`lib/submit-form.ts` explicitly targets "plain static hosting (e.g. Bluehost public_html)"). Confirm the target host before switching output modes.
